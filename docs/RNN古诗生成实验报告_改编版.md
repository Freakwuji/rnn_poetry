#### 三、模型架构

##### 3.1 最终采用模型：PoetryLSTM

```
输入:  [batch_size, seq_length]  例: [64, 48]  (64句诗，每句48字)
  │
  ▼ Embedding(vocab_size=6487, embedding_dim=128)
  [64, 48, 128]  每个字映射为 128 维向量
  │
  ▼ LSTM(input_size=128, hidden_size=256, num_layers=2, dropout=0.5, batch_first=True)
  [64, 48, 256]  提取时序特征
  │
  ▼ Dropout(p=0.5)    训练时随机丢弃 50%
  [64, 48, 256]  防止过拟合
  │
  ▼ Linear(256 → 6487)
  [64, 48, 6487]  映射回词表维度
  │
  ▼ CrossEntropyLoss（训练时）/ Top-k采样（生成时）
```

##### 3.2 各组件详解

| 组件 | 输入→输出 | 参数量 | 作用 |
|:----|:---------|:------|:------|
| **Embedding** | (6487, 128) | **830,336** | 独热编码→稠密向量，含义相近的字向量距离近 |
| **LSTM 层1** | (128→256) | **394,240** | 提取时序特征，遗忘门/输入门/输出门控制信息流 |
| **LSTM 层2** | (256→256) | **525,312** | 第二层捕捉更高阶的时序模式 |
| **Dropout** | — | **0** | 随机丢弃 50% 神经元，防止过拟合 |
| **Linear** | (256→6487) | **1,661,272** | 映射到词表大小 |
| **合计** | — | **~3.4M**（含偏置） | — |

##### 3.3 LSTM 门控机制

LSTM（Long Short-Term Memory）通过三个门解决传统 RNN 的梯度消失问题：

```
遗忘门: f_t = σ(W_f · [h_{t-1}, x_t] + b_f)
  控制"忘记什么"——保留重要信息，丢弃不相关的

输入门: i_t = σ(W_i · [h_{t-1}, x_t] + b_i)
  控制"记住什么"——决定哪些新信息存入细胞状态

输出门: o_t = σ(W_o · [h_{t-1}, x_t] + b_o)
  控制"输出什么"——从细胞状态中提取哪些信息

细胞状态更新: C_t = f_t * C_{t-1} + i_t * tanh(W_C · [h_{t-1}, x_t] + b_C)
隐藏状态: h_t = o_t * tanh(C_t)
```

**与简单 RNN 的对比：** 简单 RNN 在反向传播时梯度指数级衰减，只能记住 ~10 步前的信息；LSTM 通过门控机制让梯度顺畅流动，可记住 100 步以上的长距离依赖。

#### 四、训练配置

##### 4.1 超参数

| 超参数 | 值 | 选择依据 |
|:------|:---|:---------|
| 优化器 | **Adam** | 自适应学习率，无需手动调参 |
| 初始学习率 | **0.001** | Adam 论文推荐默认值 |
| 调度器 | **CosineAnnealingLR** | 余弦退火，平滑衰减 |
| 损失函数 | **CrossEntropyLoss(ignore_index=0)** | 忽略 `<PAD>` 位置 |
| 批次大小 | **128** | GPU 内存与收敛速度的平衡 |
| 序列长度 | **48** | 覆盖常见诗句长度 |
| 梯度裁剪 | **max_norm=5.0** | 防止梯度爆炸 |
| Dropout | **0.5** | 标准推荐值 |

##### 4.2 训练循环细节

```
一轮训练 (1 epoch)：
  for each batch (128 个样本序列):
    1. 取出 inputs [128, 48] 和 targets [128, 48]
    2. 前向传播:
       嵌入层: inputs → [128, 48, 128] 字向量
       LSTM:  → [128, 48, 256] 隐藏状态
       输出层: → [128, 48, 6487] 每个位置×每个字的分数
    3. 计算损失: CrossEntropyLoss(预测分数, 真实标签)
       loss = -Σ log(softmax(score)[correct_idx])
    4. 反向传播: loss.backward() 自动求导
    5. 梯度裁剪: clip_grad_norm_(5.0)
    6. 参数更新: optimizer.step()
    7. 学习率调度: scheduler.step()

生成 (inference):
  输入起始字 "春"
  循环直到 max_length 或 <EOS>:
    1. 模型输出 next_token_logits [6487]
    2. 温度缩放: logits /= temperature
    3. Top-k 过滤: 只保留概率最高的 k 个字
    4. Softmax 归一化 → 概率分布
    5. 按概率采样 → 选一个字
    6. 拼接到输入 → 继续
```

##### 4.3 生成参数调优

| 参数 | 取值范围 | 推荐值 | 说明 |
|:----|:--------|:------|:------|
| **temperature** | 0.5~1.2 | **0.8** | 越低越保守，越高越随机 |
| **top_k** | 3~20 | **8** | 越小越保守，越大越多样 |
| max_length | 20~64 | **24** | 生成总字数 |

**温度效果对比：**
```
t=0.5: 春江春江春江春江春江春江   (过于保守)
t=0.8: 春江水夜风开雨夜寒风雨起   (推荐✅)
t=1.2: 春江翁流水子散入骑黄牛     (过于发散)
```

##### 5.5 Attention 模型实验（实验⑤⑥）

| 实验 | 模型 | 参数量 | 准确率 | 生成效果 |
|:----|:-----|:------:|:------:|:--------|
| ⑤ | biLSTM+Attention | 17.8M | 62.64% | 词表仅 213 字，质量受限 |
| ⑥ | LSTM+Attention | 9.7M | **80.81%** | 生成重复字 ❌ |

**Attention 机制原理：**

```
Attention(Q, K, V) = softmax(QK^T / √d_k) · V

在古诗生成中：
  Q = 当前要预测的字（查询）
  K = 前面所有字的位置（键）
  V = 前面所有字的特征（值）
  → 生成每个字时"回头看"前面的所有字
  → 选择性关注关键信息（如开头押韵的字）
```

**实验⑥的教训：** Attention 模型在 52 轮时触发早停（验证 Loss 连续 15 轮未下降），准确率 80.81% 但生成全是重复字。原因是 Attention 模型在古诗这种短文本（20-40 字）上过于强大，拟合过度导致模型坍塌。

#### 六、对照实验分析

##### 6.1 2×3 析因实验设计

```
固定条件：LSTM 模型 + 6,487 词表 + Adam 优化器
两个因素：数据（2水平）× 轮数（3水平）
```

| 数据 \ 轮数 | **30轮** | **100轮** | **200轮** |
|:----------|:--------:|:---------:|:---------:|
| **唐诗 57K** | ⑦ 3.99% | ⑧ 4.54% | ③ 6.07% |
| **多朝 98K** | ⑨ 10.28% | **⑩ 11.41%** | ④ 17.72% |

**6 组实验全部变量明确，无混淆：**

| 对照类型 | 对比实验 | 固定因素 | 唯一变量 | 结论 |
|:---------|:---------|:---------|:---------|:-----|
| 轮数主效应（唐诗） | ⑦→⑧→③ | 数据+模型 | 轮数 | 30→200轮 +2.08% |
| 轮数主效应（多朝） | ⑨→⑩→④ | 数据+模型 | 轮数 | 30→200轮 +7.44% |
| 数据主效应（30轮） | ⑦→⑨ | 模型+轮数 | 数据 | 唐诗→多朝 +6.29% |
| 数据主效应（100轮） | ⑧→⑩ | 模型+轮数 | 数据 | 唐诗→多朝 +6.87% |
| 数据主效应（200轮） | ③→④ | 模型+轮数 | 数据 | 唐诗→多朝 +11.65% |

##### 6.2 因子效应分析

```
准确率
  │
17%╶     ───────── ④ 多朝200轮 17.72%
15%╶    ╱
13%╶   ╱
11%╶─●─────────── ⑩ 多朝100轮 11.41%
 9%╶  ╱           ⑨ 多朝30轮 10.28%
 7%╶─●─────────── ③ 唐诗200轮 6.07%
 5%╶──●─────────── ⑧ 唐诗100轮 4.54%
 3%╶──●─────────── ⑦ 唐诗30轮 3.99%
  │
  └──────────────────────── 轮数
      30      100      200
```

**分析：**

**（一）数据主效应（Data Main Effect）**

固定轮数不变，仅改变数据集，观察准确率变化：

| 轮数 | 唐诗57K | 多朝98K | 差值 | 效应量 |
|:----:|:-------:|:--------:|:----:|:------:|
| 30轮 | 3.99% | **10.28%** | **+6.29%** | +158% |
| 100轮 | 4.54% | **11.41%** | **+6.87%** | +151% |
| 200轮 | 6.07% | **17.72%** | **+11.65%** | +192% |

数据效应在三个轮数水平上均高度显著。多朝数据包含宋诗、宋词、元曲、明清诗等多样化风格，词表中出现了"烟霞"、"渔樵"、"鸥盟"等唐诗中少见的词汇，丰富了模型的学习空间。

**（二）轮数主效应（Epoch Main Effect）**

固定数据集不变，仅增加训练轮数，观察准确率变化：

| 数据集 | 30轮→100轮 | 100轮→200轮 | 全程总计 |
|:------|:----------:|:-----------:|:--------:|
| 唐诗57K | +0.55% | +1.53% | **+2.08%** |
| 多朝98K | +1.13% | +6.31% | **+7.44%** |

两个数据集的准确率均随轮数递增，但增速不同。多朝数据集在 100-200 轮阶段出现加速增长（+6.31%），而唐诗数据集在该阶段增速仅为 +1.53%。说明**复杂数据集需要更多训练才能充分挖掘其潜力**。

**（三）交互效应（Interaction Effect）**

```
准确率提升率（30→200轮）
        │
  8%╶   ───────── ● 多朝98K：+7.44%
        │
  4%╶
        │
  2%╶   ───────── ● 唐诗57K：+2.08%
        │
        └────────────────── 数据集
              唐诗57K      多朝98K
```

数据×轮数之间存在**正向交互效应**。多朝数据集在 200 轮时的准确率（17.72%）不仅高于同期唐诗（6.07%），其增长斜率也更大。这意味着：
1. 数据多样性带来更高的准确率天花板
2. 丰富的训练数据能从更长的训练中获取更大收益
3. 简单数据集（唐诗57K）在 30 轮后即接近饱和

**（四）生成质量与准确率的背离**

虽然多朝数据在准确率上全面领先，但生成诗句的"唐诗韵味"反而不如纯唐诗模型。以 30 轮为例：

| 指标 | 唐诗模型（⑦） | 多朝模型（⑨） |
|:----|:-------------|:--------------|
| 准确率 | 3.99% | **10.28%** |
| 生成样例 | 春江水夜风开雨夜寒风雨起 | 春江山月上秋风吹花满云中 |
| 唐诗语感 | ✅ 更纯正 | ⚠️ 混入宋词词汇 |

这一背离说明准确率衡量的"下一个字猜中率"与人类感知的"诗歌质量"并非同一概念。

##### 6.3 有效对照 vs 无效对照

| 对照组 | 固定因素 | 唯一变量 | 结论有效？ |
|:-------|:---------|:---------|:----------|
| ⑦→⑧→③ | 唐诗57K+LSTM+6487词表 | **轮数** | ✅ 有效对照 |
| ⑨→⑩→④ | 多朝98K+LSTM+6487词表 | **轮数** | ✅ 有效对照 |
| ⑦→⑨ | LSTM+30轮+6487词表 | **数据** | ✅ 有效对照 |
| ⑧→⑩ | LSTM+100轮+6487词表 | **数据** | ✅ 有效对照 |
| ③→④ | LSTM+200轮+6487词表 | **数据** | ✅ 有效对照 |
| ①→② | — | 数据+词表**同时变** | ❌ 无效对照 |
| ④→⑤ | — | 模型+词表**同时变** | ❌ 无效对照 |

**5 组有效对照占总对照 71%**，构成了完整的析因分析基础。

##### 6.4 仍缺欠的对照

```
固定：唐诗57K + 30轮 + 6487词表
  LSTM       → 3.99% ✅（实验⑦）
  LSTM+Attn  → ?%     ❌ 缺失
```

LSTM vs LSTM+Attention 的同条件对比实验因代码版本冲突未能完成，是当前实验的最大缺口。此外，以下对照也可作为后续补充：
- **优化器对比**：SGD vs Adam（固定其他条件）
- **词表规模对比**：1000 子词表 vs 6487 全词表
- **模型深度对比**：1层LSTM vs 2层LSTM vs 3层LSTM

#### 七、关键发现

1. **准确率 ≠ 生成质量：** 实验⑥ Attention 模型准确率高达 80.81%，但生成全是重复字；实验⑦ 纯 LSTM 准确率仅 3.99%，但生成的诗句可读、意象丰富。准确率衡量的是"猜字能力"，而非"作诗能力"。

2. **2×3 析因实验验证：** 6 组实验覆盖了数据（唐诗、多朝）× 轮数（30、100、200）的全部组合，5 组有效对照均呈一致趋势。多朝数据在各轮数下准确率均高于唐诗 6-12%，且轮数×数据存在正交互效应——大容量多朝数据从更多训练中获益更大（30→200轮 +7.44%，唐诗仅 +2.08%）。

3. **数据质量 > 数据数量：** 57K 纯唐诗的生成效果远优于 138K 混合数据。合成/扩增数据虽然增加了数量，但引入了大量重复模式，反而降低了生成多样性。

4. **词表大小决定多样性：** 6,487 字词表虽使准确率降低，但生成的诗句词汇丰富；213 字词表准确率高，但翻来覆去只有几十个字，缺乏古诗韵味。

5. **简单模型在古诗任务上更稳定：** LSTM 在 30 轮内即可稳定收敛，生成可读诗句。Attention 模型在短文本任务上容易过拟合，导致模型坍塌。

5. **GPU 加速效果显著：** 超算 A100 训练速度为本地 CPU 的约 10 倍（每轮 5s vs 50s），200 轮训练从 3 小时缩短到 20 分钟。

### 【小结】

#### 心得体会

本次实验从零搭建了一套完整的古诗词生成系统，覆盖了数据处理、模型设计、超算部署、超参调优、生成测试的全流程。共进行 7 组对比实验，累计训练超过 700 轮，涵盖了不同数据集、不同模型架构、不同训练策略的组合。

**核心结论：** 古诗词生成任务中，简单 LSTM + 高质量纯唐诗数据是最佳组合。复杂模型（Attention）和扩增数据虽然在某些指标上表现更好（准确率高达 80%），但实际生成质量反而不如简单方案。

**技术收获：**
- 掌握了 LSTM 的门控机制和工作原理
- 理解了 Embedding 层如何将离散的汉字映射为连续的语义空间
- 实践了 Top-k 采样和温度调节对生成质量的影响
- 学会了使用 Slurm 在超算上提交和管理 GPU 训练任务

#### 遇到的问题及解决

| 问题 | 原因 | 解决 |
|:----|:-----|:------|
| Windows GBK 不兼容 emoji | 终端编码限制 | 设置 stdout=utf-8 replace 模式 |
| scp 传输失败 | 超算配置限制 | 改用 `cat > file` 方式 |
| HPC inode 配额满 | 小文件过多 | 用 `~/project/` 目录（配额更大） |

| Attention 模型生成重复 | 模型坍塌 | 用简单 LSTM 替代 |
